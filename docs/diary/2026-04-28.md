## Sezení 5 — F2 prototyp: vrstva character/ + plynulé přechody

### Diskuse

- **Volba startu F2.** Nabídl jsem 2 cesty: (a) `@THINK` nad API `Stickman` wrapperu před implementací, (b) rovnou prototyp s minimálním scope (STAND + WALK) a refaktor potom. Uživatel zvolil **(b)** — KISS varianta v duchu memory `feedback_kiss_refactor` (modul + 1 vzorové demo, zbytek nech).
- **Téma 1: API wrapperu.** Stickman drží JEN `{ skeleton, status, time, params }` — ne view, ne scene. Demo si komponuje vrstvy podle potřeby (1 demo = 1 skeleton + 1 view, akvárium F3 = N skeletonů + N views + 1 scene). Snap-to-floor zůstává v demu, ne ve Stickmanu (= některé budoucí stavy SWIM/CLIMB snap nepotřebují).
- **Téma 2: Animační funkce.** Tvar `fn(skeleton, time, params) → void`, mutuje skeleton přímo (volá `setAngle`). Žádný return value. Defaulty parametrů exportované jako konstanta (`DEFAULTS_WALK`) — single source pro slidery v demu, demo si přes spread merge přepíše jen to, co potřebuje.
- **Téma 3: Bug v init demo02.** První verze prošla HTTP 200 ale prohlížeč ukázal jen tlačítka, žádného panáka. Příčina: `addButtonGroup(panel, items, callback, activeKey)` synchronně volá callback při init (`if (activeKey) activate(activeKey)`), ale callback referuje `tempoUI`/`ampUI`/… které jsou deklarované teprve POD ním → **TDZ ReferenceError** "Cannot access 'tempoUI' before initialization" → zbytek skriptu padl, scéna se nikdy nespustila. Fix: nepředávat `activeKey` do `addButtonGroup`, po vytvoření sliderů zavolat `bg.activate(Status.STAND)` ručně.
- **Téma 4: Iterace A+B.** Po prototypu uživatel zvolil obě následující iterace najednou:
  - **A (rychlý win):** SIT a LAY pose-based stavy. Každý 1 řádek v `Animations.js` (`sit.apply` / `layBack.apply`). 4 tlačítka v demo02.
  - **B (infrastruktura):** Plynulé přechody mezi stavy. `setStatus()` udělá `Pose.capture` snapshot, `animate()` během `transitionDuration` (default 0.4 s) lerpuje z snapshotu do výstupu nové animace.
- **Téma 5: Easing — proč cubic ease-out.** Tři alternativy: linear (mechanický pocit), ease-out (rychlý start, měkký dojezd, organické), ease-in-out (pomalá reakce — vstup/výstup z scény). Cubic = `1 − (1−t)³`, kompromis mezi jednoduchostí a vizuální kvalitou.
- **Téma 6: Edge case mid-transition switch.** Důležité: když uživatel přepne stav uprostřed běžícího přechodu, `Pose.capture` zachytí AKTUÁLNĚ blended pózu (ne původní `transitionFrom`), takže nový přechod plynule pokračuje z aktuálního stavu, žádný "skok zpět". Proto se snapshot dělá v `setStatus()`, ne v `animate()`.

### Rozhodnutí

- **Vrstva `src/character/` založena** se 3 soubory: `Status.js` (enum, frozen, stringy), `Animations.js` (registr `Status → fn`), `Stickman.js` (wrapper). Prototyp implementuje 4 stavy: STAND, SIT, WALK, LAY (zbylých 6 jsou v enum jako konstanty pro budoucí rozšíření).
- **API contract animační funkce:** `fn(skeleton, time, params) → void`. Žádný state mimo skeleton, žádný return. Single signature platí pro pose-based i procedurální cyklické animace. **Důvod:** stejný interface umožní pozdější blending (Pose.capture snapshotem výstupu).
- **`DEFAULTS_WALK` jako single source defaultů**, demo i `setStatus(Status.WALK)` v Animations čtou ze stejné konstanty. Slidery v demo02 se inicializují z tohoto objektu.
- **Plynulé přechody přes `Pose.capture` + `Pose.lerp`** — žádný extra animation system, jen znovupoužití existujícího Pose API. Snapshot v `setStatus()`, blend v `animate()`, easing aplikován na `t` PŘED lerp.
- **`Stickman.transitionDuration = 0.4 s` default**, lze přepsat zvenčí (`stickman.transitionDuration = 0.6`). Public property, žádný setter.
- **Stavy bez registrované animace = no-op** (postava zůstane v poslední pose). Záměrně, ať Stickman nepadá na neimplementovaných stavech (důležité při postupném dopisování F2).
- **Render loop pattern:** demo volá `stickman.animate(dt)` → `skel.snapToFloor()` → `view.update()` → `view.updateMarkers()`. Pořadí kritické: animace mutuje úhly + root, snap srovná na podlahu, view čte výsledek.
