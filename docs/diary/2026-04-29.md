## Sezení 8 — F2.1: Demo 02 přepsaný + Drift + Run + Neklid + Dance preset

### Diskuse

- **Otevření.** Z „Příště" Sezení 7 první bod: implementovat Drift v F2. Uživatel chtěl rovnou demo02 přepsat podle vzoru Demo 01 — vlevo POSES (Reset, Drift), pod tím STATUS (Walk, Jog, Sprint), zbytek (původní WALK slidery, stats panel, toggles) odebrat.
- **Téma 1: Architektura — Drift, Walk, Run.** Z @THINK návrhu: Reset = STAND bez params; Drift = `setStatus(STAND, { idle: true })` (= animateStand rozhoduje podle params.idle); Walk = existující animateWalk; Jog/Sprint = nový `animateRun` s `RUN_PRESETS.jog/sprint`. Drift = budget-based random walk podle spec v IDEAS.md. Lazy state v `params._drift` — per-Stickman, ne global. Quint ease-out per cyklus.
- **Téma 2: Sprint kalibrace.** Po prvním pokusu uživatel napsal: „U sprintu osu těla mírně předklonit dopředu" + „Koleno přední nohy trochu výše". `forwardLean` 22° → 30°, `kneeLift` 130° → 150° (knee drive blízký anatomickému max 165°).
- **Téma 3: První rozšíření — pravý panel s Drift parametry + Dance.** Uživatel: chce slider Neklid 0–10 + Bio/Fyzio (= postava se občas podrbe / prohrábne vlasy / vymění stojnou nohu) v pravém panelu; Drift má zahrnout i 3 root osy; Dance jako alternativa k Drift (omezený root pro stabilitu, ale rytmický). Oponoval jsem zařazení Bio/Fyzio do téhle iterace — výrazně víc kódu (state machine, 3+ procedurálních akcí), ne dotažený Drift. Dohodli jsme se odložit Bio/Fyzio do IDEAS, místo toho v této iteraci dotáhnout Drift + Dance.
- **Téma 4: Dance jako separátní animace.** První pokus: `animateDance` jako sin-based procedurální animace (BPM, sway, weight shift, head bob, paže v antifázi). DEFAULTS_DANCE + Status.DANCE registr. Pravý panel: dvě sekce (Drift Neklid 0-10, Dance BPM 60-200).
- **Téma 5: Reframe — Dance jako preset, Neklid jako globální overlay.** Druhé kolo uživatele: „Neklid je obecný parametr pro VŠECHNY pózy a stavy, ne specifický pro Drift" + „Dance ať je mnohem divočejší, jako drift do rytmu" + „Drift ať umožní plný pohyb root" + „Dance parametr [BPM slider] odebrat". To vedlo k zásadní architektonické změně:
  - **Neklid = globální overlay** v `src/util/Neklid.js` — sin per-osa s deterministickou frekvencí (hash), aplikuje se PO `Stickman.animate` v render loopu, funguje pro VŠECHNY režimy (Walk, Sprint, Drift, Reset)
  - **Dance = preset** Status.STAND idle: `{ idle: true, fraction: 0.5, cycleDuration: 60/110, rootRange: 8 }` = drift v rytmu, omezený root. Žádný separátní animateDance, žádný Status.DANCE registr — KISS, méně kódu, jednotné API
  - **Drift `rootRange`: 8° → 90°** — postava se může nakloněit do horizontály. Argumentoval jsem proti plných ±180° (postava by se za 4-5 cyklů otočila na hlavu = ne stand idle)
- **Téma 6: Bug fix `skeleton.reset()`.** Při návrhu animateDance jsem narazil na latentní bug existujících animací: `animateWalk` / `animateRun` nastavují jen některé klouby (hipL/R.x, kneeL/R.x, ...). Po Drift → Walk by úhly z Driftu (např. shoulderL.z, neck.z, torso.z) přetrvávaly v ne-přepsaných osách napořád. Fix: `skeleton.reset()` na začátku každé procedurální animace = clean slate před setAngle. Pose-based animace (animateStand pose, animateSit, animateLay) volají `pose.apply()` → ten interně dělá reset, takže OK.
